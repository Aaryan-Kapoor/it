# Showing a page, and what the command says of the displays

`--open` on `it create` or `it update`, and `it open <id>`, ask the display the user is on to bring a page up now: of the displays with It's site open, the one they used last, and with none open, the one used last of all. Without `--open`, no display is asked, and what `it create` or `it update` prints has a `hint` that says the page is shown on no display: give the user the `url`, and show it with `it open <id>` if they want it on a screen. Leave out `--on` unless the user named a display, and use `--everywhere` only when they asked for every screen. `--on "<name>"` names one display by its name, and `--on-id <id>` by the id `it displays` prints. `shownOn` in what is printed names the displays that were asked, and `hint` says why that one. Asked is all it says: a display with the site open brings the page up at once, one whose browser is closed does not open by itself, and It does not wait to hear that a page was drawn. So tell the user which displays were asked, and do not tell them that you can see the page on a screen. **If `shownOn` is empty and there is neither `notShown` nor `notShownOn`, no display was asked and nobody can see the page: give the user the `url`, and tell them that no display is paired.** Where the one display you named takes nothing now, the command is refused as `it notify` is, with the code `agents_off` or `not_paired` and a status other than 0, and its `hint` gives the page's link; with `--open` the page is published and that code is `notShown.code`. Say that of that display, and not that none is paired. The `hint` printed beside it says how they pair one: `it site`, run on the machine It runs on, opens the site in a browser there and pairs that browser, and other screens are added from that one. If `notShown` is there, the page was published and asking the displays went wrong: read `notShown.code` before you say anything about displays. `not_found` means that no display has the name you gave with `--on`, or the id you gave with `--on-id`, and `it displays` lists the names and ids there are; `agents_off` and `not_paired` are the display you named taking nothing now, as above. Any other code (`rate_limited`, `offline`, `timeout`) says nothing about which displays are paired, and a request that ran out of time may have reached a display all the same. Whatever the code, keep the `id` and the `url` you were given and do not publish the page again: `it open deploy-plan` asks the displays once more. If `notShownOn` is there, it lists each other display with a `reason`. `not_chosen` is a display passed over for the one in use, which needs no word to the user. `not_paired`: the pairing of that display's browser was ended, and the display shows nothing until that browser is paired again. `agents_off`: the user closed that display to agents, and only they can open it again, on that display or under Displays; never ask them to, unless they want the page there. `locked`: the user locked that display to another page, and it keeps to it. No command of yours unlocks it, and nothing you do may get around it: if the page belongs there, ask the user to unlock the display, on the display itself or under Displays, and wait for them. A lock only keeps that display on its page: it does not keep anyone at the display from other pages' state or actions. A locked display still gets notifications: `it notify` reaches it with `--everywhere`, `--on` or `--on-id`, and with no display named where it is the one in use, and it stays on its page. The page is published, and the displays in `shownOn` were asked to show it. Tell the user of a display you named that shows nothing, as the `hint` says, give them the `url` if `shownOn` is empty, and do not publish again.

One case lies between a command that worked and one that failed: `it create` or `it update` with `--open`, when the page was published and could then not be shown, prints the page as usual on standard output, with `notShown` beside it, and exits with status 1.

Each display has `paired`, which is `false` for one whose browser's pairing was ended: it shows nothing until that browser is paired again. `it displays` lists them.

`it notify "<text>" [--id <id>] [--on "<display>"]` sends a short message outside any page, to the display the user is on unless you name one, and `sentTo` says where. With `--everywhere` it goes to every display there is now, and to none paired later. A display named that cannot take it, or none that can, is refused with the code `agents_off`, `not_paired` or `nowhere`, and nothing is sent. A name two displays share is refused: send it by `--on-id`. A display with the site open shows it at once. One without gets it as a notification only where its browser can show one, the user has allowed that there, and nobody has yet seen the message on another display.
