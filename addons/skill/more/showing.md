# Showing a page, and what the command says of the displays

`--open` on `it create` or `it update`, and `it open <id>`, ask a display to bring a page up now. With no `--on`, that is one display: the one the user is on, which is the display with It's site open that they used last, or, where none has the site open, the one they used last of all. That is the right place for nearly everything, so leave `--on` out unless the user named a display. `--on "<display>"` asks the display of that name and no other, and `--on all` asks every display: use it only when the user asked for the page on all of their screens. The user can close a display to agents on the site, and It then never asks that display, by name or with `--on all`.

`shownOn` in what is printed names the displays that were asked. Asked is all it says: a display with the site open brings the page up at once, one whose browser is closed does not open by itself, and It does not wait to hear that a page was drawn. So tell the user which display was asked, and do not tell them that you can see the page on a screen. Where you named no display, the `hint` says whether the one asked had the site open. If it did not, the page comes up there only when the site is next opened and the page is chosen, so the link is how the user gets to it. **If `shownOn` is empty and there is neither `notShown` nor `notShownOn`, no display was asked and nobody can see the page: give the user the `url`, and tell them that no display is paired.** The `hint` printed beside it says how they pair one: `it site`, run on the machine It runs on, opens the site in a browser there and pairs that browser, and other screens are added from that one.

If `notShownOn` is there, it lists each display the page is not shown on, with a `reason`:

- `not_chosen`: you named no display, and another one was chosen. Nothing is wrong with this display, and nothing need be said of it unless the user asks where the page is.
- `not_paired`: the pairing of that display's browser was ended, and the display shows nothing until that browser is paired again.
- `agents_off`: the user closed that display to agents, on the display itself or on the site under Displays. Only the user can open it to agents again, and you should not ask them to unless they wanted the page there.

Where `notShownOn` names the display you asked for, it is that display that shows nothing, and the reason beside it says why: say that of that display, and not that none is paired. The page is published, and the displays in `shownOn` were asked to show it. Give the user the `url` if `shownOn` is empty, and do not publish again.

If `notShown` is there, the page was published and asking the displays went wrong: read `notShown.code` before you say anything about displays. `not_found` means that no display has the name you gave with `--on`, and `it displays` lists the names there are. Any other code (`rate_limited`, `offline`, `timeout`) says nothing about which displays are paired, and a request that ran out of time may have reached a display all the same. Whatever the code, keep the `id` and the `url` you were given and do not publish the page again: `it open deploy-plan` asks the displays once more.

One case lies between a command that worked and one that failed: `it create` or `it update` with `--open`, when the page was published and could then not be shown, prints the page as usual on standard output, with `notShown` beside it, and exits with status 1.

`it displays` lists the displays. Each display has `paired`, which is `false` for one whose browser's pairing was ended, and `agents`, which is `false` for one the user closed to agents.

`it notify "<text>" [--id <id>] [--on "<display>"]` sends a short message outside any page, to a display chosen as `it open` chooses one, and to every display with `--on all`. What it prints has `sentTo`, the displays it went to, and `notSentTo`, each other display with a `reason` as above. A display with the site open shows the message at once. One without gets it as a notification only where its browser can show one, the user has allowed that there, and nobody has yet seen the message on another display. A display you name that cannot take it is refused with the code `not_paired` or `agents_off`, and nothing is sent. With no display named, where no display can take it, the notification is refused with the code `nowhere` and nothing is sent: the `hint` says why of each display. `--on all` keeps it for every display instead, which has it once it can take it.
